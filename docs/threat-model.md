# Threat model

Trust boundaries: web content → shell; other browsers' profiles → import; filter lists → rule compiler; page text → AI model; AI model → CLI helper; extensions → pages and shell; update source → app; other apps → URL handler; sync storage → app; disk.

The "Status" column records what the code enforces today. Algorithms, key lengths and TLS
settings per client are in `cryptography.md`; the actors, components and external interfaces in
`architecture.md`.

|---|---|---|---|---|
| S1 | Critical | A web page reaches shell functions through a JS bridge or an internal page | No script message handlers in tab web views. Internal pages use a separate configuration and data store, bundled assets only, strict CSP; web content cannot link to, embed or navigate to them. | Tab web views get no script message handler; `tarn:` is blocked for web sources in `nav_policy`. Popups use WebKit's own configuration, so they keep the opener's request context. Snippets, and an assistant answer the user inserts with Insert into Page (macOS and Windows), reach a page only through the user's command; an answer may carry what another attached page said, so it reaches the focused field's site only by that click: `page_scripts::insert_text_script` runs once in the isolated world (none under Lockdown) and types the text into the focused field with `execCommand`, skipping password fields; `;name` expansion happens in shell fields only, and no world of the page gets a key listener. Capture Area and Measure draw over a still snapshot in the shell; the Capture Element picker answers only a rectangle. Ask Assistant about Selection and its commands read the selection with the same `SELECTED_TEXT` script after the user picks the entry in the page's own menu (isolated world on macOS, Windows, Linux and iOS; on Android the page-world answer goes through `page_ops::selection_answer`), so no text comes from a password, one-time-code or card field and nothing is read under Lockdown (`ask_assistant_reads_the_selection_with_its_command_but_never_a_secret_field`, `the_selection_is_read_but_never_from_a_secret_field`); the menu entries add no script or listener to the page. |
| S17 | Critical | Page text injects instructions into the Claude CLI, which can run commands and read files | Helper runs the CLI with tools and MCP disabled, fixed arguments, no shell, prompt on stdin, minimal environment, empty temporary working directory, timeout and output cap. Binary path is absolute, chosen by the user, and must not be world-writable. The helper accepts connections only from our signed app. If tool disabling cannot be confirmed, the provider refuses to run. | `tarn-cli-bridge` enforces the CLI rules: fixed arguments, `--help` probe, stdin prompt, only `HOME` and `PATH=/usr/bin:/bin`, own process group killed when the run ends or times out, and the binary plus every ancestor directory owned by the user or root and writable only by them, `wheel` or `admin`. Not reachable from the packaged app only because `scripts/bundle.sh` does not ship the helper: the app runs without the App Sandbox, so a child would no longer inherit one. The XPC helper and its caller check are not built. An npm-installed CLI (`#!/usr/bin/env node`) does not start with that `PATH`. |

A selection command's answer goes only to the chat, never into the page; the answer's links are also listed as keyboard stops under it (macOS and Windows tab stops, NSH buttons) that open through the same `links::classify` confirmation. |

Commands run on the system's on-device model when it is available and the cloud was chosen; with a local choice that cannot answer the chat says why and asks no cloud, and every answer names the model that gave it (`ai::local::answer`: `commands_stay_on_the_device_when_it_can_answer_and_say_who_answered`; `commands_answer_on_the_device_and_name_it_while_questions_go_where_chosen`). |

A nightly on the Release channel counts the release feed as current for its release version (`channel_version`) and is offered only a later release. A check counts as verified for the Chromium staleness gate only if the signed appcast lists the running version or a later one, so an old appcast replayed through a release asset no longer keeps Chromium open; one listing the running version still does. Windows, Linux and mobile release files are built unsigned from pinned containers and a pinned rustup-init but with unpinned distribution packages and Gradle dependencies; they are attested by a job that runs none of their code, and each build job can add only its own file names to the release. A portable Windows Tarn (`browser_core::portable_dir`) checks the same signed feed but downloads and starts no installer; it stays on its version until the user replaces it, and the Chromium staleness gate closes its Chromium tabs as on every install. |

Only Safari web extensions bundled with apps in `/Applications` are offered (`engine::extensions`); nothing runs until the user turns an extension on for the current profile in Settings › Extensions, which lists every requested permission and site pattern. Tarn has no internal web pages to reach. **Page scripts on Android (S1, S14).** Contract v3's reader, page-text, Find in Tabs text and element-picker
scripts, and the selection, media, Insert Snippet and Capture Element scripts, run in the page's own world on Android, which has no isolated world without a JavaScript bridge. A
page can see and change those scripts' globals and forge their answers (an async script's answer is held
in a `window` property with a random 128-bit name until the component polls it). What a forged answer can
do is bounded in Rust: `Article::parse` and `clip_history_text` keep only plain text of the page's own
document, Find in Tabs matches the query in Rust (the query never reaches the page), and a picked selector
is stored only when `valid_zap` accepts it, for the host the tab still shows, a selection or media answer
is handed on only as `page_ops::selection_answer` or `page_ops::media_answer` writes it back (bounded
plain text and checked numbers), an Insert Snippet answer is only a yes or no, and a picked rectangle is
cut to the visible page (`capture::element_area`), so a page can at most hide parts of itself, put its
own text into its reader view, history search or mini-player, or report a wrong media state. Scripts never run when
JavaScript is off (Lockdown). They run only when the user asks: opening the reader, Find in Tabs (every
live tab's page, once per page while a search goes on), the element picker, Capture Element, Insert Snippet and
the mini-player's buttons; the reader probe other
platforms send after each load is never sent on Android. The one exception is full-text history, off by
default: while it is switched on, every finished http(s) page of a normal space runs the page-text script,
so a page can notice a Tarn user who turned it on (a script ran in its world). The hung-page ping runs
the selection script on the shown page every `lifecycle::PING_EVERY` (2 s), and the mini-player reads the
media script of a tab when it plays or is left and every `media::POLL` (2 s) while it plays, so any page
can notice it runs in Tarn on Android; only "answered" is kept from a ping, never the text. A page that watches its own
world can also see the reader, Find in Tabs and picker runs when the user starts them. browsing runs in a separate process with its own WebView data directory inside the app's
credential-encrypted storage; that directory is deleted when the private space closes and, after a crash,

next launch, like the private space. Not verified on a physical device.

## Risks that remain

These cannot be closed by this design; they are documented for users.

- A WebKit zero-day stays open until Apple ships a fix and the user installs it.
- Deep fingerprinting protection and encrypted DNS inside the app are not possible on WKWebView.
- The private-network rule matches addresses, not DNS answers, so DNS rebinding is only partly covered.
- An extension the user grants broad permissions can read those pages.
- Website styles from a theme, once turned on, can make text on the sites they name hard to read.
- Malware already running as the user can read the profile database and Keychain items it is allowed to see.
- Once a user allows Tarn to read another browser's Safe Storage key, macOS may let Tarn read it again without asking.
- With Claude enabled, Anthropic receives the page content the user sends.
- No blocker catches every ad: ads served from the same host and path as content, and video ads
  stitched into the stream by the server, pass. YouTube can change its player and break the
  YouTube script until the bundle's `youtube.json` or an app update follows.
- WebKit's fraudulent-website check asks Apple, which uses Google Safe Browsing, about hashed
  address prefixes; the malware switch turns it off together with the lists.
